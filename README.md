# AIАгент1С

AI-агент на платформе **1С:Enterprise** в виде **расширения** конфигурации: агентский цикл
с tool calling, MCP-клиент, память диалога и интерактивный HTML-чат. Работа с моделью —
через любой OpenAI-совместимый endpoint (`/v1/chat/completions`).

Все объекты агентной части — собственные объекты расширения с префиксом `СИ_`.
Совместимость расширения 8.3.24, платформа 8.5.1. Базовая конфигурация — на БСП 3.2.1
(разрабатывается и тестируется на «БиблиотекаСтандартныхПодсистемДемо» 3.2.1.569).

## Возможности

- Агентский цикл **Tool Calling**: модель предлагает вызовы инструментов, агент
  исполняет их на сервере 1С и возвращает результат в цикле до готового ответа.
- Подключение к любому **OpenAI-совместимому** endpoint — OpenAI, **Ollama**, vLLM,
  LM Studio, шлюзы.
- **Инструменты 1С**: запросы к базе, схема метаданных, диагностика журнала регистрации,
  выгрузка в Excel, диаграммы, обзорные сводки, калькулятор, Mermaid, файлы диалога.
- **Распознавание изображений и PDF (vision)**: картинки и постраничное распознавание
  PDF через vision-модель; PDF рендерится внешним движком (pdftoppm / Ghostscript /
  ImageMagick).
- **MCP-клиент**: подключение внешних серверов по JSON-RPC (initialize, tools/list,
  tools/call), транспорты StreamableHTTP и SSE; инструменты сервера попадают в общий
  реестр агента, а встроенные инструменты могут сами вызывать MCP (например, Mermaid).
- **Память диалога**: факты, релевантный отбор, сводка, TTL.
- **Контроль безопасности**: подтверждение вызовов пользователем, права 1С, безопасный
  режим, белый/чёрный список объектов в запросах к БД.
- Чат-интерфейс на поле HTML: markdown, эмодзи, темы, индикатор шагов, файлы и картинки.

## Структура репозитория

- `AIAgent1CExtension/` — EDT-проект расширения (все правки вносятся только сюда).
- `AISSL/` — EDT-проект базовой конфигурации БСП-демо; каркас для привязки расширения.
- `Серверы/` — автономный сервер с ИБ для отладки (рабочие данные).
- Правила разработки — в [AGENTS.md](../AGENTS.md).

## Установка и быстрый старт

1. Подключите расширение к информационной базе на БСП-конфигурации
   (из EDT — привязкой к базовому проекту, либо загрузкой собранного `.cfe`).
2. Запустите обработку **«Чат агента»** (`СИ_ЧатАгента`) и откройте **Настройки**:
   укажите `base_url` OpenAI-совместимого endpoint, ключ авторизации и модель
   (для локальной Ollama: `http://localhost:11434/v1`, тип авторизации «Нет»).
   При первом получении настроек значения заполняются по умолчанию.
3. Зарегистрируйте встроенные инструменты — кнопкой в форме списка справочника
   **«Инструменты агента»** (`СИ_ИнструментыАгента`) или программно (см. ниже).
4. Выберите режим работы **Tool Calling** (константа `СИ_АктивныйРежим`) — именно в нём
   работает агентский цикл с инструментами.
5. Включите регламентное задание **«Обслуживание агента»** (`СИ_ОбслуживаниеАгента`) —
   оно чистит просроченную память диалогов и снимает зависшие фоновые заходы.
6. Проверьте подключение и начните диалог в чате.

Пользователям для работы с чатом достаточно роли `СИ_ИспользованиеСИ_ЧатАгента`.

## Подключение к LLM: OpenAI-совместимый API

Взаимодействие с моделью построено на OpenAI-совместимом протоколе
(`/v1/chat/completions`) с полем `tools` (function calling); повторы при транспортных
ошибках — по умолчанию 2. HTTP-клиент — `СИ_ОpenAIКлиент`, настройки —
`СИ_НастройкиАгента`, редактирование — форма «Настройки» обработки «Чат агента».

Основные параметры: `БазовыйURL`, `КлючAPI`, `МодельПоУмолчанию`, температура
(по умолчанию 0.2), таймаут (60 с), прокси, лимит итераций агентского цикла
(`MaxIterations`, по умолчанию 10), лимиты истории и сжатия контекста.

**Профили подключений** (`СИ_ПрофилиПодключений`) позволяют хранить несколько endpoint'ов
и переключать их вместе с режимом работы — например, облачная модель для чата и
локальная Ollama для распознавания картинок. Доступность endpoint можно проверить
действием «проверить подключение» (запрос списка моделей).

### Типы авторизации (`СИ_ТипыАвторизации`)

| Тип | Как передаётся ключ |
|-----|---------------------|
| `Bearer` | заголовок `Authorization: Bearer <ключ>` (по умолчанию) |
| `КлючВЗаголовке` | ключ в произвольном заголовке (имя задаётся в настройках) |
| `КлючВURL` | ключ как query-параметр URL |
| `Нет` | без авторизации — локальные endpoint'ы |

### Ollama

Локальные модели подключаются напрямую: Ollama поддерживает тот же
OpenAI-совместимый интерфейс.

- `БазовыйURL`: `http://localhost:11434/v1` (или адрес машины с Ollama).
- Тип авторизации: **«Нет»** — ключ не нужен.
- `МодельПоУмолчанию`: имя модели из `ollama list` (например, `qwen2.5:14b`).
- Для распознавания картинок указывайте multimodal-модель (`llava`, `qwen2-vl` и т.п.)
  в реквизите «Модель распознавания картинок» режима работы (см. ниже).
- Прокси и проверка SSL настраиваются так же, как для внешних endpoint'ов.

## Регистрация инструментов

### Как устроен реестр

Единый реестр инструментов — справочник **`СИ_ИнструментыАгента`**. В нём живут
инструменты двух типов (перечисление `СИ_ТипыИнструментов`):

| Тип | Где лежит | Что хранится |
|-----|-----------|--------------|
| `Инструмент1С` | элемент справочника | обработчик — экспортная функция общего модуля |
| MCP | табличная часть «Инструменты» справочника `СИ_MCPСерверы` | имя инструмента на сервере, ссылка на сервер |

Для модели оба типа выглядят одинаково: поле `tools` собирается в формате OpenAI
function-calling (`СИ_УправлениеИнструментами1С.СформироватьПолеТools`), а диспетчер
`ВызватьИнструмент` сам маршрутизирует вызов — в BSL-функцию или в `tools/call` MCP-сервера.

Ключевые реквизиты элемента реестра: `ИмяФункции` (уникальное имя для модели), `Описание`,
`ПараметрыSchema` (JSON Schema), `ИмяФункцииОбработчика` (`"Модуль.Функция"`), `Разрешен`,
`ТребуетРазрешения`, группа (иерархия справочника), `Слова`, `Действие`, ТЧ
`РазрешённыеРежимы`.

### Программная регистрация

Точка входа — `СИ_УправлениеИнструментами1С.ЗарегистрироватьИнструмент(ОписаниеИнструмента)`.
Дескриптор удобно собирать хелпером `ДескрипторИнструмента` — он за вас оформит JSON Schema
(`type: object` + `properties` + `required`):

```bsl
// 1. Схема параметров (JSON Schema properties)
Свойства = Новый Соответствие;
СвойствоВыражение = Новый Соответствие;
СвойствоВыражение.Вставить("type", "string");
СвойствоВыражение.Вставить("description", "Арифметическое выражение, например 2 + 3 * 4");
Свойства.Вставить("Выражение", СвойствоВыражение);

Обязательные = Новый Массив;
Обязательные.Добавить("Выражение");

// 2. Значения реестра: группа, ключевые слова, действие для индикатора чата
ЗначенияРеестра = СИ_УправлениеИнструментами1С.ЗначенияРеестра(
    "Основные",                 // группа (папка реестра)
    "посчитай, вычисли, сколько", // ключевые слова вопроса
    "Считаю выражение");         // статус шага в чате

// 3. Регистрация
Успех = СИ_УправлениеИнструментами1С.ЗарегистрироватьИнструмент(
    СИ_УправлениеИнструментами1С.ДескрипторИнструмента(
        "Calculate",
        "Точный расчёт арифметического выражения (синтаксис 1С).",
        Свойства,
        Обязательные,
        "СИ_Инструменты1С.Калькулятор", // обработчик: "ИмяМодуля.ИмяФункции"
        Ложь,                           // ТребуетРазрешения: подтверждение пользователем
        ЗначенияРеестра));

Если НЕ Успех Тогда
    // ошибка записи или конфликт имён с MCP-инструментом (детали — в журнале регистрации)
КонецЕсли;
```

Регистрация выполняется **на сервере**. Только `Имя` обязательно, остальные ключи
необязательны:

| Ключ | Тип | Назначение |
|------|-----|------------|
| `Имя` | Строка | уникальное имя функции для модели (латиница, camelCase) |
| `Описание` | Строка | семантика инструмента для модели; влияет на то, когда её будут вызывать |
| `Параметры` | Соответствие | JSON Schema параметров (`ДескрипторИнструмента` собирает сам) |
| `Обработчик` | Строка | `"ИмяМодуля.ИмяФункции"` — экспортная функция общего модуля |
| `РазрешенныеРежимы` | Массив ссылок `СИ_РежимиРаботы` | в каких режимах агента доступен инструмент; пусто/Неопределено — во всех |
| `ТребуетРазрешенияПоУмолчанию` | Булево | запрашивать подтверждение пользователя перед исполнением (пишущие инструменты) |
| `Группа` | Строка | папка реестра; отсутствующая группа создаётся автоматически |
| `Слова` | Строка | ключевые слова вопроса через запятую (см. «Группы и ленивое подтягивание») |
| `Действие` | Строка | человекочитаемый статус шага для индикатора чата («Смотрю остатки товара…») |

**Идемпотентность** (важно для повторных вызовов):

- Повторная регистрация существующего имени обновляет `Описание`, `ПараметрыSchema`
  и `Обработчик`.
- Ключи `Группа` / `Слова` / `Действие` при значении `Неопределено` у существующего
  элемента **не меняются** — ручные правки администратора не затираются.
- `ТребуетРазрешенияПоУмолчанию` применяется **только при создании** нового элемента;
  пользовательский флаг у существующего сохраняется.
- Имя, занятое MCP-инструментом, даёт отказ (`Ложь`) и запись в журнале регистрации.
- Регистрацию безопасно вызывать при каждом обновлении конфигурации — она сработает
  как «обновить описание, если изменилось».

Для инструментов без группы и слов есть короткий хелпер:
`ЗначенияРеестраДействие("Считаю выражение")`.

### Контракт обработчика

Обработчик — **экспортная функция серверного общего модуля**:

```bsl
// Параметры:
//  Аргументы - Структура - параметры, которые передала модель
//    (движок конвертирует Соответствие из tool_calls в Структуру).
//
// Возвращаемое значение - Структура:
//  * Успех    - Булево.
//  * Значение - Произвольный - результат; сериализуется в JSON и уходит модели.
//  * Ошибка   - Строка,Неопределено - текст ошибки при Успех = Ложь.
Функция Калькулятор(Аргументы) Экспорт
	Результат = Новый Структура("Успех, Значение, Ошибка", Ложь, Неопределено, Неопределено);
	...
	Возврат Результат;
КонецФункции
```

- Если обработчик вернул не структуру или структуру без ключа `Успех`, движок считает
  вызов успешным, а возвращённое значение — результатом.
- В `Значение` можно дополнительно положить служебные ключи, которые **изымаются до
  сериализации** и модели не уходят:
  - `СсылкиОбъектов` — карта ссылок на объекты для «упоминаний» в чате;
  - `Диаграмма` — карточка диаграммы (SVG, заголовок, файл диалога) — показывается
    пользователю, как у инструмента `DrawChart`.
- Движок сам: проверяет доступность инструмента в режиме, детектирует отказ по правам
  доступа 1С (`НетПрав` + инструкция модели «ДОСТУП ЗАПРЕЩЁН»), применяет гигиену
  результата (маскирование `|` перед отдачей табличных данных в markdown-ответ),
  считает длительность вызова.

**Доверенные модули.** Обработчики модулей `СИ_Инструменты1С`, `СИ_ФайлыДиалога`,
`СИ_РаспознованиеИзображений` вызываются без безопасного режима и **без `Вычислить`** —
через статическую диспетчеризацию (`ВыполнитьБезБезопасногоРежима`). Список методов там
**ручной**: при регистрации нового инструмента доверенного модуля его метод нужно
добавить в эту ветку, иначе вызов упадёт с «Неизвестный метод доверенного модуля».
Обработчики из любого другого модуля вызываются через `Вычислить` под безопасным
режимом платформы и в дополнительных настройках не нуждаются.

### Группы и ленивое подтягивание (fetch_toolset)

Чтобы не переполнять промпт, реестр раздаёт инструменты по группам:

- Инструменты группы **«Основные»** (пустая группа трактуется как «Основные») всегда
  передаются модели в поле `tools`.
- Инструменты остальных групп («Диагностика», «Выгрузки и диаграммы», «Сводки», …)
  модель подтягивает сама виртуальным инструментом **`fetch_toolset`**, а также группа
  целиком поднимается в промпт, если вопрос пользователя совпал с ключевыми словами
  (`Слова`) любого инструмента группы.

Поэтому новую группу создавайте осмысленно: «Основные» — то, без чего агент не работает,
остальные — специализированные наборы с ключевыми словами.

### Подтверждение вызовов пользователем

Инструменты с флагом `ТребуетРазрешения` перед исполнением попадают в регистр
`СИ_ОжидающиеРазрешения`; в чате появляется запрос подтверждения, решение пользователя
запоминается в `СИ_РазрешенияИнструментовДиалога`. Ставьте флаг всем **пишущим**
инструментам (создание документов, файлов, отправка внешних запросов). По умолчанию
он выставлен у `DrawMermaid` и файловых инструментов на запись.

### Регистрация из интерфейса

Форма списка справочника «Инструменты агента» умеет регистрировать встроенные наборы
кнопкой «по умолчанию» — выполняются `СИ_Инструменты1С.ЗарегистрироватьИнструменты()`
и `СИ_ФайлыДиалога.ЗарегистрироватьИнструменты()`. Требуется роль
`СИ_ДобавлениеИзменениеСИ_ИнструментыАгента`.

### Встроенные инструменты

| Инструмент | Группа | Что делает |
|------------|--------|------------|
| `ExecuteDBQuery` | Основные | запрос к БД (обязательные директивы `РАЗРЕШЕННЫЕ` и `ПЕРВЫЕ`) |
| `GetMetadataSchema` | Основные | схема метаданных конфигурации |
| `GetCurrentDateTime` | Основные | текущие дата и время |
| `ParsePeriod` | Основные | разбор словесного периода («прошлый месяц») в даты |
| `Calculate` | Основные | точный расчёт арифметического выражения |
| `DrawMermaid` | Основные | Mermaid-диаграмма в файл диалога (через MCP `render_mermaid`) |
| `CreateDialogFile` / `UpdateDialogFile` / `ReadDialogFile` / `ListDialogFiles` | Основные | файлы диалога |
| `RecognizeImage` | Основные | распознавание изображений и PDF (vision-модель) |
| `GetRecentErrors` | Диагностика | свежие ошибки пользователя из журнала регистрации |
| `ExportTable` | Выгрузки и диаграммы | выгрузка данных в Excel |
| `DrawChart` | Выгрузки и диаграммы | диаграмма-карточка в чате |
| `GetSalesSummary` / `GetMoneySummary` / `GetStockSummary` | Сводки | обзорные сводки (доступны при наличии объектов демо-конфигурации) |

### Описание базовых инструментов

**Запросы к данным**

- **`ExecuteDBQuery`** — read-only запрос к БД.
  Параметры: `ТекстЗапроса` (обязательный, на языке запросов 1С, начинается с
  `ВЫБРАТЬ`; директивы `РАЗРЕШЕННЫЕ` и `ПЕРВЫЕ` добавляются автоматически,
  модифицирующие операторы запрещены), `Параметры` (именованные параметры: даты —
  строкой `ГГГГ-ММ-ДД`, отбор по ссылке — через текстовые поля Код/Наименование,
  массивы — для `В (&Параметр)`), `ТаймаутСекунд` (по умолчанию 60), `ЛимитСтрок`
  (1–100, по умолчанию 100). Возвращает строки и флаг `ЕстьЕщеДанные`. Запрещённые
  объекты (константа `СИ_ЗапрещенныеОбъектыЗапросов`) недоступны; в выборку
  рекомендуется включать ссылочное поле (`Ссылка`) — тогда объекты кликабельны в чате.
- **`GetMetadataSchema`** — схема метаданных для составления запросов. Параметр
  `Поиск` (`"Справочник"` — все справочники, `"Справочник.Польз"` — подстрока внутри
  класса, пусто — статистика по классам) или `ИмяТаблицы` (точное имя таблицы →
  реквизиты с типами). Запрещённые объекты не возвращаются.
- **`GetCurrentDateTime`** — текущие дата и время информационной базы (без параметров):
  `ДатаВремя`, `Дата`, `Год`, `Месяц`.
- **`ParsePeriod`** — границы периода, названного словами («за 3 квартал», «в прошлом
  месяце», «за последние 30 дней»). Параметр `Текст` (можно весь вопрос — период будет
  найден). Возвращает `Распознан`, `ДатаНачала`/`ДатаКонца`,
  `НачалоДатаВремя`/`КонецДатаВремя` (их передают параметрами запроса) и `Пояснение`.

**Расчёты и графика**

- **`Calculate`** — точный расчёт арифметического выражения (синтаксис 1С: `+ - * /`,
  скобки, десятичная точка). Параметр `Выражение`; допустимы только цифры, операторы,
  скобки, точка и пробел — произвольный код 1С исключён.
- **`DrawMermaid`** — Mermaid-диаграмма в файл диалога. Параметры: `Код` (обязательный,
  без обрамляющих ` ```mermaid `), `Формат` (png/jpeg/webp/svg, по умолчанию png),
  `Тема` (default/neutral/dark/forest). Требует включённого MCP-сервера с инструментом
  `render_mermaid` (см. раздел MCP).
- **`DrawChart`** — диаграмма по данным запроса прямо в чате. Параметры: `ТекстЗапроса`
  (обязательный, как у `ExecuteDBQuery`), `Параметры`, `Тип` (столбцы/линия/круг),
  `КолонкаКатегорий` (по умолчанию первая колонка), `КолонкаЗначений` (вторая),
  `Заголовок`, `ЛимитТочек` (1–100, по умолчанию 30; в круговой лишние точки
  сворачиваются в «Прочие»). SVG и xlsx сохраняются в файлах диалога.
  Требует подтверждения.

**Выгрузки и диагностика**

- **`ExportTable`** — выгрузка результата запроса в Excel (.xlsx) в файлы диалога.
  Параметры: `ТекстЗапроса` (обязательный), `Параметры`, `ЛимитСтрок` (1…100 000,
  по умолчанию 10 000), `ИмяФайла` (.xlsx). Модель не получает сами строки — только имя
  файла, число строк/колонок, первые 5 строк и итоги по числовым колонкам, поэтому
  инструмент подходит и для больших выборок. Требует подтверждения.
- **`GetRecentErrors`** — свежие события журнала регистрации текущего пользователя.
  Параметры: `Минут` (по умолчанию 60, максимум 1440), `Уровни` (Ошибка,
  Предупреждение, Информация, Примечание; по умолчанию первые два). Возвращает до
  30 событий (Дата, Уровень, Событие, Метаданные, Данные, Комментарий).
- **Сводки** (`GetSalesSummary` / `GetMoneySummary` / `GetStockSummary`) — готовые
  обзорные сводки (продажи, деньги, склад) без составления запросов. Доступны, когда
  в базе есть соответствующие объекты демо-конфигурации.

**Файлы диалога**

- **`CreateDialogFile`** / **`UpdateDialogFile`** — создание и изменение файлов диалога
  (требуют подтверждения пользователя), **`ReadDialogFile`** / **`ListDialogFiles`** —
  чтение и просмотр списка. На файлах допустимых типов построено распознавание:
  `RecognizeImage` распознаёт приложенный файл (см. раздел «Распознавание изображений
  и PDF»).

### Инструменты MCP

Внешние инструменты подключаются справочником **`СИ_MCPСерверы`** — Model Context
Protocol превращает любые внешние возможности в инструменты агента: рендеринг графики,
работа с файловой системой, поиск, корпоративные сервисы и т.д.

- **Транспорты** (перечисление `СИ_ТипыПодключенийMCP`): `StreamableHTTP` — JSON-RPC
  поверх HTTP POST (современный транспорт), `SSE` — Server-Sent Events (legacy).
- **Подключение**: URL, версия протокола, произвольные заголовки (`ЗаголовкиJSON`),
  авторизация (Bearer / ключ в заголовке / ключ в URL), таймаут вызова, проверка SSL,
  флажок **Включен**.
- **Протокол**: клиент `СИ_УправлениеИнструментамиMCP` выполняет `initialize`
  (с согласованием версии протокола и уведомлением об инициализации), затем `tools/list`
  — список попадает в табличную часть «Инструменты» элемента справочника. Загрузку
  можно повторять (опционально очищая инструменты, исчезнувшие с сервера); отдельным
  действием доступна проверка подключения.
- **Доступ построчно**: для каждого инструмента сервера задаются `Разрешен`,
  `ТребуетРазрешения` и разрешённые режимы — те же механизмы, что у инструментов 1С.
- **Общее пространство имён**: имена MCP-инструментов попадают в единый реестр;
  при конфликте имён движок подбирает уникальное API-имя на основе идентификатора
  сервера, поэтому внешние имена не могут вытеснить встроенные.
- **Вызов** выполняется через `tools/call`; для модели MCP-инструмент ничем не отличается
  от встроенного — диспетчер `СИ_УправлениеИнструментами1С.ВызватьИнструмент`
  маршрутизирует вызов сам.
- **Двусторонняя интеграция**: встроенные инструменты могут сами быть клиентами MCP —
  `DrawMermaid` обёрнут над MCP-инструментом `render_mermaid` и сохраняет результат
  как файл диалога.

### Получение описаний и удаление

- `СИ_УправлениеИнструментами1С.ПолучитьОписаниеИнструмента(Имя)` — полное описание
  (включая тип, обработчик, режимы, группу).
- `ПолучитьСписокИнструментов(Фильтр)` — список с фильтрами по типу (`"1С"`/`"MCP"`),
  режиму и белому списку имён; объединяет оба типа.
- `УдалитьИнструмент(Имя)` — для инструмента 1С ставит пометку удаления, для
  MCP-инструмента снимает флажок `Разрешен` в ТЧ сервера.

## Распознавание изображений и PDF (vision)

Распознаванием занимается модуль `СИ_РаспознованиеИзображений`; инструмент —
`RecognizeImage` (работает по файлу, приложенному к диалогу).

- **Форматы**: картинки `jpg`, `jpeg`, `png`, `gif`, `bmp`, `webp` и PDF.
- **Как работает**: картинка уходит vision-модели блоком `image_url` как data URI
  (base64) через тот же OpenAI-совместимый API; слишком большие картинки пережимаются
  в JPEG с ограничением размера стороны, чтобы base64 не раздувал запрос.
- **Какая модель**: реквизиты **«Модель распознавания картинок»**
  (`МодельРаспознованияКартинок`) и **«Профиль распознавания картинок»**
  (`ПрофильРаспознованияКартинок`) в элементе справочника `СИ_РежимиРаботы` — vision
  можно направить на отдельный профиль (например, локальная Ollama с `llava`, пока
  основной чат идёт в облако). Если модель не задана, инструмент вернёт ошибку
  «Не задана модель распознавания картинок».
- **PDF обрабатывается постранично**: страницы конвертируются в JPG внешней утилитой,
  каждая страница распознаётся отдельно, тексты склеиваются (`=== Страница N ===`).
  Настройки (раздел настроек агента):

  | Настройка | По умолчанию | Смысл |
  |-----------|--------------|-------|
  | `ДвижокКонвертацииPDF` | `pdftoppm` | движок рендеринга: `pdftoppm` (poppler-utils), `ghostscript` (на Windows `gswin64c`), `imagemagick` (`magick`) |
  | `ПутьКУтилитеКонвертацииPDF` | пусто | полный путь к утилите, если её нет в `PATH` |
  | `МаксимумСтраницPDF` | 10 | сколько первых страниц конвертировать |
  | `DPIКонвертацииPDF` | 100 | разрешение рендеринга страниц |

  Утилита выполняется на сервере 1С (при файловом варианте — на клиентской машине),
  поэтому её нужно установить там, где работает код.

## Безопасность

- **Права 1С соблюдаются всегда**: отказ доступа превращается в инструкцию модели,
  а не в падение агента.
- **Запросы к БД**: только с директивами `РАЗРЕШЕННЫЕ` и `ПЕРВЫЕ`; чёрный список
  объектов — константа `СИ_ЗапрещенныеОбъектыЗапросов` поверх неотключаемого
  внутреннего списка; выражения калькулятора проверяются по белому списку символов.
- **Безопасный режим платформы**: обработчики недоверенных модулей исполняются
  только под ним.
- **Подтверждение пользователем** — для пишущих инструментов (см. выше).
- Лимит длины ответа модели — константа `СИ_ЛимитТокеновНаОтвет`; ограничения
  агентского цикла (число итераций, таймауты) — в `СИ_Агент1С`.

## Обслуживание
